# Clash 免费节点从哪来、能不能用：来源与风险
更新:2026-11-05 · 依据:来源页面自述与项目文档

Clash 免费节点的公开页面中，有的是从网络内容聚合而来。能取得订阅不代表节点长期有效，也不代表适合登录重要账号。

## 这些节点从哪里来？

已记录的个别页面自述，内容由其他公开内容合并而来。聚合是将已有信息收集在一起，不等于这些服务器由页面维护者自己运营。

不能把个例改写成所有来源的共同做法。节点是谁运营、聚合页面由谁维护，也不能直接当成同一个问题。

## 哪些风险要分开看？

有页面直接提醒速度慢、节点会失效，并提示运营者能看到流量。这是来源自己的风险说明，不是对全部节点进行测试后的统计。

| 风险说明 | 使用时怎样处理 |
| --- | --- |
| 速度慢 | 不把它当作持续可用的保证 |
| 随时失效 | 不因当前可连就认定以后也能连接 |
| 运营者可看到流量 | 不用于网银、重要账号或支付 |

自动更新处理订阅内容，健康检查处理可达性。两者都不能把来源的风险提示变成已经解决的问题。

## 写着更新就仍在维护吗？

更新宣传要和实际推送记录分开看。截至 2026-11-05，一个自述每小时更新的仓库，最近推送仍停在 2026-09-05。

这个例子说明文字描述与推送记录可以不同。它没有给出全部来源的失效比例，也不能据此判断某次推送中的节点都可连接。

## 自动更新能解决什么？

自动更新可重新取得订阅内容，不能保证每个节点有效。订阅响应带 `profile-update-interval` 时，客户端可按它更新，单位是小时。

`url-test` 是用于连接检查的策略组，可自动跳过连不上的节点。这里的检查只覆盖 `proxies`，不覆盖通过 `use` 引入的代理集合。

- 内容更新不等于逐个节点都能连接。
- 可以连接不等于适合处理重要账号事务。
- 不能把临时可用直接作为长期方案的依据。
