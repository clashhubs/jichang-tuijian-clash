# 机场推荐 Clash 版 2026 · 订阅导入与内核选择（持续更新）

用 Clash 的人挑机场，比别人多两道关卡：**第一，机场得给得出 Clash 能吃的订阅**；**第二，你手上的客户端得跟机场的内核对得上**。很多人买完才发现链接导不进去、或者导进去节点全红，问题几乎都出在这两处，而不是"速度慢"。

所以这份清单不排速度、不排性价比，只回答一件事：**用 Clash 的人该怎么选机场、怎么把订阅弄进去、导不进去怎么修。** 表里唯一的硬指标是"订阅链接支持情况"——这是能不能用的前提，不是体验好坏的问题。

> 本页不含任何测速、延迟、解锁率数字。没有统一口径的实测就不写，也不转载来源不明、无法复现的数据。价格与订阅支持情况均标注核对日期，过期了就是过期了。

## 一、先选客户端：Verge Rev / mihomo / ClashX 到底选哪个

这三个名字经常被混着说，其实**两个是"壳"，一个是"芯"**：

| | 是什么 | 平台 | 谁该用 |
| --- | --- | --- | --- |
| **mihomo（原 Clash Meta）** | **内核**，真正干活的那个进程 | 全平台（命令行 / 被 GUI 调用） | 想跑在软路由、NAS、VPS 上，或要自己写完整配置的人 |
| **Clash Verge Rev** | GUI 外壳，内置 mihomo 内核 | Windows / macOS / Linux | **绝大多数桌面用户选它**，开箱即用又能改配置 |
| **ClashX / ClashX Meta** | GUI 外壳，macOS 专属 | macOS | 只用 Mac、想要最轻的菜单栏工具 |

选择顺序，照这个来就不会错：

1. **Windows / Linux 桌面** → Clash Verge Rev。原版 Clash 内核早已停止维护，现在拿到的订阅普遍带 `vless` / `hysteria2` / `tuic` 这类新协议，**只有 mihomo 内核认得**，Verge Rev 默认就是 mihomo。
2. **macOS** → ClashX **Meta** 版（注意是 Meta，不是老 ClashX），或者同样装 Verge Rev。老版 ClashX 用的是已停更的内核，遇到新协议直接解析失败。
3. **软路由 / NAS / 常驻服务** → 直接跑 mihomo 内核 + 自己维护 `config.yaml`，配 `proxy-providers` 定时拉订阅。
4. **手机端**不在本页范围内（Clash 系在移动端的分发状况变化太快，写下来很快就过期）。

**一句话判断法：** 如果你的订阅导进去报 "unsupported proxy type"，八成不是机场的问题，是你的壳里包着一个老内核。换 mihomo 系的壳即可。

## 三、订阅导入失败：按顺序排查这五步

**不要跳步。** 90% 的问题在前两步就解决了，从第三步开始才需要动配置。

### 第 1 步：确认链接类型不是"通用订阅"

机场后台常同时给几条链接：Clash 订阅、通用订阅（base64）、v2ray 订阅。**只有标着 Clash / mihomo 的那条能直接导入。** 通用订阅粘进 Verge Rev 通常表现为"导入成功但一个节点都没有"。

后台没有 Clash 专用链接的，看第二节表里的③档——很可能这家本来就不提供。

### 第 2 步：确认你是在"未连接代理"的状态下拉订阅

订阅地址本身经常需要能连上外网才拉得到。**首次导入时，如果系统代理指向的是一条已经失效的旧配置，会形成死锁**：拉不到订阅 → 没有可用节点 → 更拉不到订阅。

解决：先关掉系统代理，或临时切到"直连"模式，再点更新。

### 第 3 步：看错误信息里的关键词，对号入座

| 报错里出现 | 含义 | 怎么修 |
| --- | --- | --- |
| `unsupported proxy type` | 内核太老，不认新协议 | 换 mihomo 内核的客户端（见第一节） |
| `yaml: unmarshal errors` | 拉回来的不是 YAML，多半是 HTML 错误页 | 把订阅链接直接贴浏览器打开看返回了什么 |
| `403` / `404` | 链接过期、被重置、或复制时截断 | 回后台重新复制完整链接 |
| 超时 / 无响应 | 订阅域名本身不可达 | 见第 4 步 |

### 第 4 步：订阅域名不可达 —— 换域名，不是换机场

这个垂直里，**机场的订阅域名被封锁是常态，寿命常以天计**。域名不通不代表账号或节点坏了。

处理方式：去机场的 TG 频道 / 官网公告找**当前有效的备用域名**，把订阅链接里的域名部分换掉，其余路径与参数保持原样，重新导入。

### 第 5 步：导入成功但节点全红

先分清是"全红"还是"测不出来"：

- **全部节点显示超时，但能上网** → 多半是延迟测试用的测速地址被墙了，改测试 URL（例如换成 `http://www.gstatic.com/generate_204`）后重测。
- **全部节点显示超时，且不能上网** → 检查是否套了另一层代理、或系统代理没打开。
- **只有部分节点红** → 正常现象，那几个落地点可能在维护，换一个用。
- **节点列表是空的** → 回到第 1 步，你导的多半是通用订阅。

## 四、策略组与规则分流：最小可用配置

不用一上来就抄几千行的规则集。**下面这份是能跑起来的最小骨架**，理解它之后再往上加。

```yaml
proxy-providers:
  airport:
    type: http
    url: "你的 Clash 订阅链接"
    interval: 3600          # 每小时自动更新一次订阅
    path: ./providers/airport.yaml
    health-check:
      enable: true
      url: http://www.gstatic.com/generate_204
      interval: 300

proxy-groups:
  # 手动选择：兜底用，出问题时切到这里逐个试
  - name: "手动选择"
    type: select
    use: [airport]

  # 自动选择：按延迟挑最快的，日常主力
  - name: "自动选择"
    type: url-test
    use: [airport]
    url: http://www.gstatic.com/generate_204
    interval: 300
    tolerance: 50           # 差距小于 50ms 不来回切，避免频繁抖动

  # 总开关：所有规则最终指向它
  - name: "PROXY"
    type: select
    proxies: ["自动选择", "手动选择", "DIRECT"]

rules:
  - GEOIP,LAN,DIRECT           # 局域网直连
  - GEOIP,CN,DIRECT            # 国内 IP 直连
  - MATCH,PROXY                # 其余走代理
```

**三个概念说清楚就够了：**

- **`proxy-providers`** —— 订阅的来源。写在这里，节点由内核自己定时拉，不用手动更新。
- **`proxy-groups`（策略组）** —— 一组节点 + 一个挑选规则。`select` 是你手点，`url-test` 是按延迟自动选。规则里永远指向**策略组**，不要直接指向某个节点名，否则订阅一更新、节点改名，规则就全断了。
- **`rules`（规则）** —— 从上往下匹配，**命中即停**。所以顺序很重要：`MATCH` 必须放最后一行，它是兜底。

**加规则的正确姿势**：在 `MATCH` 之前插入，例如让某个域名强制直连：

```yaml
rules:
  - DOMAIN-SUFFIX,example.com,DIRECT
  - GEOIP,LAN,DIRECT
  - GEOIP,CN,DIRECT
  - MATCH,PROXY
```

改完配置**别忘了在客户端里重新加载/切换一次配置**才生效，光保存文件不够。

## 五、FAQ

**Q：Clash Verge Rev 和 Clash Meta 到底有什么区别？**
不是同一层的东西。Clash Meta（现名 mihomo）是**内核**，Verge Rev 是**图形界面**，且 Verge Rev 内置的就是 mihomo 内核。所以"我该用 Verge Rev 还是 Meta"这个问题本身不成立——用 Verge Rev 时你已经在用 Meta 内核了。

**Q：订阅不更新、节点还是旧的怎么办？**
按这个顺序查：① 客户端里该配置的"自动更新间隔"是否设成了 0；② `proxy-providers` 里的 `interval` 单位是**秒**，写成 3600 是一小时，别误写成 3600 天的量级；③ 手动点一次更新看是否报错，报错就回到第三节第 3 步；④ 有些客户端会缓存旧配置，删掉这条配置重新导入一次最干脆。

**Q：节点全红是机场跑路了吗？**
不一定，先看第三节第 5 步。真正判断机场状态要看：官网/后台能不能打开、客服有没有回应、TG 频道最后一条公告是什么时候。**单凭客户端里一片红色下结论，最常见的误判来源是测速地址被墙。**

**Q：为什么有的机场给的链接导进 Clash 是空的？**
你拿到的多半是"通用订阅"（一串 base64），那是给 v2ray 系客户端用的。回后台找标着 Clash 的那条。如果后台压根没有，参考第二节的③档——这家就是不提供。

**Q：一定要用订阅链接吗？**
不一定。有的机场主推自家客户端，配置由客户端内部处理，不对外给订阅链接（见第二节①档）。这种方案上手更省事，代价是你没法用自己习惯的 Clash 客户端和自定义规则。**看你更在意省事还是可控。**

**Q：能不能同时导入多家机场的订阅？**
可以。`proxy-providers` 下面可以写多个条目，各自一条 `url`，再在同一个策略组里 `use: [airport1, airport2]`。这也是最实用的容灾方式——一家挂了还有另一家。
